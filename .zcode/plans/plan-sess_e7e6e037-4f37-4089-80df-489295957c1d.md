# Liens partageables : fiche détaillée véhicule/suite + aperçu Discord dynamique

## Contexte (état actuel)
- Le bouton Partager copie déjà `vehicules.html?select=avenger4` (`shareVehicleLink`, `src/modules/09-showroom-pagination.ts:440`).
- À l'ouverture d'un tel lien, `loadPublicVehicles()` (`src/modules/07-vehicles-showroom.ts:250-269`) ouvre le **modal de réservation** (formulaire), pas une fiche du véhicule.
- 2 bugs connexes : le paramètre `?select=` n'est jamais retiré de l'URL (aucun `history.replaceState` dans tout `src/`), donc chaque événement realtime Supabase **rouvre le modal** ; et les balises OpenGraph de `vehicules.html`/`suites.html` sont statiques → aperçu Discord générique.
- Les suites ont le même mécanisme en miroir (`12-suites-showroom.ts:47-66`, `shareSuiteLink:252`).

## 1. Fiche détaillée véhicules (nouveau modal vitrine)
- **`vehicules.html`** : ajouter un overlay `#vehicle-detail-modal-overlay` juste après le modal de réservation, en réutilisant les classes CSS existantes (`.luxury-reservation-modal-*`) pour hériter du style. Contenu : zone image (src = `extractItemMediaArray` première photo, clic → `openRichmanLightbox(id,'vehicule')` pour la galerie), rangée de badges (statut dispo via `getVehicleRentalSchedule`, classe, plaque), titre (`formatLuxuryCarName`), chip note (clic → `openVehicleReviewsModal`), description (`specs.specs_text`), prix `/24h`, boutons **Partager** (`shareVehicleLink`) et **Réserver** (ouvre le modal de réservation existant).
- **`src/modules/10-dropdowns-grid.ts`** (où vit déjà `openVehicleReservationModal`, lignes 186-283) : ajouter `window.openVehicleDetailModal(vehicleId)` / `closeVehicleDetailModal` selon la même convention (`.active` + `aria-hidden`, fermeture au clic sur fond et bouton X).
- Bonus UX : clic sur le titre d'une card de la grille ouvre la fiche détaillée (le média continue d'ouvrir la lightbox, les boutons existants ne changent pas).

## 2. Correction du flux `?select=` véhicules
- **`src/modules/07-vehicles-showroom.ts:250-269`** : le paramètre ouvre désormais `openVehicleDetailModal` (au lieu du modal réservation), puis **nettoie l'URL** via `history.replaceState(null, '', window.location.pathname)` → corrige la ré-ouverture en boucle au fil des events realtime. Scroll vers `#showroom-section` conservé. Matching tolérant actuel (id / nom exact / inclusion) conservé ; véhicule introuvable → comportement actuel (scroll simple).

## 3. Réplication côté suites
- **`suites.html`** : même overlay `#suite-detail-modal-overlay` (galerie `media_urls`, badges, prix, description, boutons Partager/Réserver).
- **`src/modules/12-suites-showroom.ts`** : `openSuiteDetailModal` + lecture `?select=` corrigée (fiche au lieu du modal réservation + nettoyage d'URL), en miroir exact des véhicules.

## 4. Aperçu Discord dynamique (OG par véhicule/suite)
- **`api/og.ts`** (nouvelle fonction serverless Vercel, convention dossier `api/`) : reçoit `type=vehicule|suite` + `select=<name>`, interroge Supabase REST (`GET /rest/v1/vehicules?name=eq.<name>`, anon key déjà publique côté client, valeur via constante), retourne un petit HTML avec `og:title` (nom formaté + prix), `og:description` (description tronquée), `og:image` (screenshot CDN du véhicule ou `media_urls[0]` de la suite, fallback logo Supabase) + tags Twitter. Fallback 302 vers la page statique si introuvable.
- **`middleware.ts`** (racine du repo) : si User-Agent correspond à un robot connu (Discordbot, TelegramBot, Twitterbot, WhatsApp, Slack, facebookexternalhit…) **et** chemin `/vehicules` ou `/suites` **avec** `?select=` → rewrite vers `/api/og?type=…&select=…` ; sinon `next()` (les humains servent la page statique, zéro impact).
- Contingence : si le middleware n'est pas honoré par le build statique Vite sur Vercel (à vérifier au déploiement), plan B simple — `shareVehicleLink`/`shareSuiteLink` génèrent directement des URLs `/api/og?…` (OG pour les bots, meta-refresh vers la vraie page pour les humains).

## 5. Vérification
- `npm run build` (tsc + Vite) puis contrôle manuel sur le dev server local via le navigateur intégré : ouverture de `vehicules.html?select=avenger4` → fiche qui s'ouvre automatiquement, URL nettoyée, fermeture OK, bouton Réserver OK, idem une suite.
- Commit + push sur `main` → auto-déploiement Vercel, puis `curl -A "Discordbot…"` sur l'URL prod avec `?select=` pour valider les balises OG dynamiques.
